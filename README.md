# Лесгафт AI для университетского сообщества

Это обновлённая версия проекта. Она сделана в духе интерфейса DeepSeek: свободный белый экран чата, компактная боковая панель, история диалогов, подсказки и большое поле ввода.

Сайт предназначен для общего пользования в университете. Студент открывает публичный чат и сразу пишет вопрос. API-ключи не вводятся студентами: администратор один раз сохраняет подключения в панели управления, проверяет их и выбирает активную модель для всех пользователей.

## Что можно подключить

В панели предусмотрены:

- DeepSeek;
- OpenAI;
- Google Gemini через OpenAI-совместимый endpoint;
- Anthropic / Claude;
- Groq;
- OpenRouter.

Для каждого подключения администратор указывает название, провайдера, точный ID модели и API-ключ. Можно хранить до восьми подключений и менять активное подключение без правки сайта. Есть кнопка тестирования выбранного ИИ.

Примеры моделей, которые можно указать в кабинете соответствующего провайдера:

| Провайдер | Пример модели | Формат API |
| --- | --- | --- |
| DeepSeek | `deepseek-flash` | Chat Completions |
| OpenAI | актуальная chat-модель из кабинета | Chat Completions |
| Gemini | актуальная Gemini-модель, доступная в OpenAI compatibility | Chat Completions |
| Anthropic | актуальная Claude-модель | Messages API |
| Groq | модель из списка Groq | OpenAI-compatible |
| OpenRouter | `provider/model-name` | OpenAI-compatible |

Названия моделей со временем меняются. Вводите точное название, которое принимает конкретный сервис.

## Важно про GitHub Pages и API-ключи

GitHub Pages хранит только интерфейс. Секретный API-ключ нельзя безопасно поместить в `app.js`, `index.html`, GitHub Pages или JavaScript браузера: любой посетитель сможет его увидеть и использовать. Поэтому проект разделён на две части:

- `docs/` — публичный интерфейс, который публикуется GitHub Pages;
- `server/` — сервер Cloudflare Worker, который хранит зашифрованные ключи, проверяет права администратора и обращается к провайдерам ИИ.

Cloudflare Worker использует Durable Object с SQLite storage для настроек, зашифрованных ключей и общих лимитов. Секреты Worker задаются через Variables and Secrets и не попадают в репозиторий. В документации Cloudflare секреты можно добавлять через Dashboard или Wrangler, а SQLite-backed Durable Objects рекомендуется для новых Durable Object-классов.

## Быстрый план размещения

Нужно создать один GitHub-репозиторий, например `lesgaft-ai-university`, и один Cloudflare Worker.

1. Создайте на GitHub публичный репозиторий.
2. Загрузите содержимое этого проекта в корень репозитория. Папки `docs` и `server` должны лежать рядом.
3. Откройте **Settings → Pages**.
4. Включите **Deploy from a branch**.
5. Выберите ветку `main` и папку `/docs`.
6. Скопируйте адрес опубликованного сайта. Он будет примерно таким: `https://ВАШ-ЛОГИН.github.io/lesgaft-ai-university/`.
7. Откройте `docs/config.js` в GitHub и замените `YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev` на адрес будущего Worker. Пока Worker не создан, сайт покажет сообщение о необходимости настройки.
8. Создайте аккаунт Cloudflare и откройте **Workers & Pages → Create application → Worker**.
9. Свяжите Worker с этим GitHub-репозиторием. В настройках сборки установите корневую папку `server`, команду установки `npm install`, команду деплоя `npx wrangler deploy --config wrangler.jsonc`.
10. После первой публикации Cloudflare покажет адрес вида `https://lesgaft-ai-api.ВАШ-SUBDOMAIN.workers.dev`.
11. Вставьте этот адрес без завершающего `/` в `docs/config.js` вместо `YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev` и сохраните файл в GitHub.
12. Дождитесь обновления GitHub Pages и проверьте адрес сайта.

Если в вашей панели Cloudflare поле корневой папки называется **Root directory**, укажите `server`. Wrangler-конфигурация и `worker.js` находятся именно там. Workers Builds запускает команду сборки и деплоя при push в подключённый GitHub-репозиторий.

### Если не хотите подключать автоматическую сборку

В корне проекта можно установить Wrangler и выполнить деплой из папки `server`:

```bash
cd server
npm install
npx wrangler login
npx wrangler deploy --config wrangler.jsonc
```

После этого обновите `docs/config.js` и закоммитьте изменения в GitHub. Для первого запуска команда Wrangler создаст Durable Object namespace согласно `wrangler.jsonc`.

## Первичная настройка секретов

Секреты нужны только на стороне Cloudflare Worker:

- `ADMIN_TOKEN` — пароль администратора панели. Минимум 32 символа;
- `ENCRYPTION_KEY` — ключ шифрования API-ключей, ровно 32 случайных байта в Base64.

Их можно сгенерировать на странице `https://ВАШ-ЛОГИН.github.io/lesgaft-ai-university/admin.html`: раскройте **«Первый запуск: создать секреты сервера»** и нажмите **«Сгенерировать локально»**. Сгенерированные значения никуда автоматически не отправляются. Скопируйте их в Cloudflare Worker:

1. Откройте Worker → **Settings → Variables and Secrets**.
2. Создайте Secret `ADMIN_TOKEN` и вставьте первую строку.
3. Создайте Secret `ENCRYPTION_KEY` и вставьте вторую строку.
4. Сохраните и задеплойте Worker.
5. Удалите эти строки из открытых заметок и сохраните их в менеджере паролей.

Не меняйте `ENCRYPTION_KEY` после сохранения подключений: старые API-ключи перестанут расшифровываться. Если ключ шифрования потерян, сохранённые подключения придётся удалить и добавить заново.

## Добавление и смена ИИ

1. Откройте `/admin.html`.
2. Введите `ADMIN_TOKEN` и нажмите **«Войти»**.
3. В разделе **«Подключения»** нажмите **«Добавить»**.
4. Укажите название, провайдера, точную модель и API-ключ.
5. Нажмите **«Сохранить подключение»**.
6. В карточке нажмите **«Проверить ответ»** в нижнем разделе.
7. Если тест прошёл, нажмите **«Выбрать для всех»**.
8. В разделе **«Доступ и лимиты»** включите **«Чат доступен посетителям»**.

После этого студенты открывают обычную главную страницу. API-ключ не виден им и не передаётся в браузер. В чат отправляется только текст переписки и системная инструкция специализированного помощника.

## Ограничение тематики

Сайт работает как помощник по здоровому образу жизни. Сервер перед каждым ответом сначала отправляет вопрос в тематический фильтр. Он должен вернуть `ALLOW` или `REDIRECT`. При `REDIRECT` сервер не просит выбранную модель давать ответ на постороннюю тему, а показывает короткое перенаправление к физической активности, питанию, сну или восстановлению.

Основной ответ формируется с системной инструкцией: не назначать лекарства, не диагностировать, не давать опасные диеты, не составлять экстремальные планы и направлять к специалисту при медицинских рисках. Студенты не могут передать свой `provider`, `model`, API-ключ или системное сообщение в запросе: сервер принимает только историю сообщений и использует активное подключение из Durable Object.

Ограничение языковой моделью не является математической гарантией. Перед общим запуском нужно провести тесты на реальных примерах университета и наблюдать расходы провайдера.

## Лимиты и защита расходов

В панели настраиваются:

- общий лимит вопросов за сутки;
- лимит запросов из одной сети в минуту;
- количество одновременных запросов.

По умолчанию включены защитные значения: 500 вопросов в сутки, 60 вопросов из одной сети в минуту и 8 одновременных запросов. Один вопрос обычно вызывает две проверки провайдера: тематический фильтр и основной ответ. В Wi-Fi университета все студенты могут иметь один внешний IP, поэтому слишком маленький лимит из одной сети будет мешать группе.

Для первого занятия можно поставить дневной лимит 100–300 и постепенно увеличить его после проверки стоимости. Также установите лимиты расходов в кабинетах самих провайдеров, если такая возможность доступна.

## Что видят студенты

- Главный экран в стиле DeepSeek.
- Чат без API-настроек.
- Новый диалог и история текущего браузера.
- Кнопки-подсказки: тренировки, питание, сон и стресс.
- Светлая и тёмная тема.
- Понятные сообщения, если администратор ещё не включил чат или провайдер временно недоступен.
- Никаких административных ключей и API-ключей в HTML или JavaScript.

История диалога по умолчанию хранится только в памяти страницы. Студент может включить сохранение в настройках, тогда история остаётся в localStorage его браузера. Сервер проекта переписку не сохраняет после ответа.

## Приватность и правила для университета

Покажите студентам предупреждение: не вводить ФИО вместе с диагнозами, медицинские документы, номера телефонов и другие персональные данные. Текст запроса передаётся провайдеру, выбранному администратором; условия хранения и обработки определяются его правилами.

Сайт не является официальным сервисом НГУ им. П. Ф. Лесгафта. Название и оформление используются для учебного проекта. Перед публикацией на официальном домене согласуйте название и использование символики университета с преподавателем или ответственным подразделением.

## Файлы

- `docs/index.html` — публичный чат;
- `docs/admin.html` — панель администратора;
- `docs/app.js` — логика общего чата;
- `docs/admin.js` — логика панели подключения ИИ;
- `docs/common.js` — запросы к Worker и безопасный вывод Markdown;
- `docs/style.css` — оформление в стиле DeepSeek с акцентами Лесгафта;
- `docs/config.js` — единственная строка с публичным адресом Worker;
- `server/worker.js` — API, CORS, авторизация, лимиты, Durable Object;
- `server/providers.js` — адаптеры DeepSeek, OpenAI, Gemini, Claude, Groq и OpenRouter;
- `server/prompts.js` — системная инструкция и тематический фильтр;
- `server/wrangler.jsonc` — конфигурация Cloudflare Worker;
- `test/server.test.js` — автоматические серверные проверки.

## Проверка проекта

Запуск тестов:

```bash
npm install
npm test
```

Проверены: авторизация панели, отсутствие ключей в ответах API, шифрование ключей, CORS, все адаптеры, защита от подмены модели клиентом, тематический фильтр, лимиты при параллельных запросах, лимит одной сети, освобождение одновременных слотов, редактирование и удаление подключений, размеры запросов и rate limit панели.

Публичная страница и админ-панель дополнительно проверены в Chromium на desktop и mobile: интерфейс открывается без JavaScript-ошибок и горизонтальной прокрутки.
